# 01 — Product Spec

## 1. ปัญหา & เป้าหมาย

**ปัญหาเดิม (ในแชต LINE):**
- แอดมินต้องพิมพ์ประกาศเก็บเงินรายสัปดาห์ + แนบรูปแพลนเมนู
- สมาชิกตอบกระจัดกระจาย: ส่งสลิปบ้าง โอนพร้อมเพย์บ้าง จ่ายสด และพิมพ์ออเดอร์ไข่
  ("แอน 5 วันไข่ต้มสด", "มิ้ง 2 วัน จ ศ ไข่ต้ม", "ไข่ดาวไม่สุก 5 วัน")
- แอดมินต้องไล่จดเองว่าใครจ่ายแล้ว ใครค้าง ใครกินไข่อะไรวันไหน → ผิดพลาดง่าย ทวงยาก
- แม่ครัวต้องเดาจำนวนไข่แต่ละชนิดต่อวันเอง

**เป้าหมายของระบบ:**
1. รวมทุกอย่างไว้ที่เดียว เปิดจากในแชต LINE ได้ทันที (LIFF)
2. สมาชิกกดเลือกวัน + ชนิดไข่ + วิธีชำระ ได้ในไม่กี่แตะ
3. แอดมินเห็นภาพรวมการจ่ายเงิน กดยืนยันสลิป/เงินสดได้เอง
4. แม่ครัวเห็นสรุปจำนวนไข่/หัว ต่อวัน อัตโนมัติ

---

## 2. Personas / Roles

| Role | ใคร | สิทธิ์ |
|------|-----|--------|
| **Member (สมาชิก)** | พนักงานในกลุ่ม | ดูแพลนสัปดาห์, สั่ง/แก้ออเดอร์ของตัวเอง, เลือกไข่รายวัน, แจ้งชำระเงิน, ดูสถานะของตัวเอง |
| **Admin (ผู้ดูแล/คนเก็บเงิน)** | เช่น คนที่รับโอน (ชุติกาญจน์ฯ ในแชต) | ทุกอย่างของ member + สร้าง/แก้แพลน + ยืนยัน/ปฏิเสธการชำระ + ดู dashboard ใครจ่าย/ค้าง + ตั้งราคา/วัน |
| **Cook (แม่ครัว)** *(optional role)* | คนทำอาหาร | ดูหน้าสรุปจำนวนไข่/หัวต่อวัน (read-only). ถ้าไม่ตั้ง role นี้ ให้แอดมินส่ง/แชร์สรุปแทนได้ |

> โมเดลสิทธิ์: `member` < `cook` < `admin`. เริ่มต้นทุกคนที่ล็อกอินครั้งแรกเป็น `member`
> แอดมินคนแรกตั้งค่าผ่าน seed/config (LINE userId), จากนั้นแอดมินเลื่อนสิทธิ์คนอื่นได้

## 3. แนวคิดหลัก (Domain model — ภาษาคน)

- **สัปดาห์ (Week Plan):** หนึ่งรอบบิล = จันทร์–ศุกร์ (5 วันทำการ). แอดมินสร้างแพลนของสัปดาห์
  แล้ว "เปิด" ให้สั่ง. เก็บเงินทุก **วันพฤหัสบดี** (เป็นเส้นตายของรอบนั้น)
- **เมนูรายวัน (Daily Menu):** แต่ละวันในสัปดาห์มีเมนูหลัก 1 อย่าง (ชื่อ + รูป/หมายเหตุ)
- **ออเดอร์ (Order):** 1 สมาชิก ต่อ 1 สัปดาห์ มี 1 ออเดอร์ ประกอบด้วยรายการรายวัน
- **รายการรายวัน (Order Item):** ต่อวันที่สมาชิกเลือกกิน → ระบุ **ชนิดไข่** (+ ระดับความสุก/หมายเหตุ)
- **การชำระเงิน (Payment):** ต่อออเดอร์ (รายสัปดาห์) — วิธี = สลิป (อัปรูป) หรือ เงินสด;
  สถานะ = รอตรวจ / ยืนยันแล้ว / ปฏิเสธ. ยอดเงิน = จำนวนวันที่สั่ง × ราคา/วัน

### ชนิดไข่ (จากข้อมูลจริงในแชต)

| ค่า (enum) | ภาษาไทย | หมายเหตุ |
|------------|---------|----------|
| `boiled` | ไข่ต้ม | รองรับ "ไข่ต้มสด" |
| `fried` | ไข่ดาว | รองรับระดับสุก: ไข่ดาวสุก / ดาวไม่สุก |
| `omelette` | ไข่เจียว | |
| `none` | ไม่ทานไข่ | **สั่งข้าว แต่ไม่เอาไข่** |

- ฟิลด์เสริม `doneness` (เฉพาะไข่ดาว/ไข่ต้ม): `well` (สุก) / `soft` (ไม่สุก/ยางมะตูม) — optional
- ฟิลด์ `note` (ข้อความอิสระ เช่น "ไม่ใส่ผัก") — optional

### สถานะการสั่งต่อวัน (สำคัญ — มี 2 แบบของ "ไม่")

ในสรุปจริงของกลุ่ม มี 2 สถานะที่ต้องแยกให้ชัด:

| สถานะ | ความหมาย | ในโมเดล |
|-------|----------|---------|
| **ไม่กิน** | ไม่สั่งข้าววันนั้น (ไม่คิดเงินวันนั้น) | **ไม่มี** `order_item` ของวันนั้น |
| **ไม่ทานไข่** | สั่งข้าว แต่ไม่เอาไข่ (คิดเงินปกติ) | มี `order_item` + `egg = 'none'` |
| ต้ม/ดาว/เจียว | สั่งข้าว + เอาไข่ชนิดนั้น | มี `order_item` + `egg` ตามชนิด |

> สมาชิกบางคน "ไม่กิน" ทั้งสัปดาห์ (เช่น ในตารางที่ไฮไลต์เหลือง) → ไม่มีออเดอร์เลย
> แต่ยังต้องโชว์ในตารางสรุปว่า "ไม่กิน" ครบทุกวัน (สรุปอิงรายชื่อสมาชิกทั้งหมด ไม่ใช่เฉพาะคนที่สั่ง)

### วันทำการ
`weekday`: 1=จันทร์, 2=อังคาร, 3=พุธ, 4=พฤหัส, 5=ศุกร์ (เก็บคู่กับ `date` จริงของสัปดาห์นั้น)

### ราคา
- `price_per_day` ตั้งค่าต่อสัปดาห์ (default จากข้อมูลจริง ≈ 20 ฿/วัน — 100฿/5วัน, 40฿/2วัน)
- ยอดที่ต้องจ่าย = `จำนวนวันที่สั่ง × price_per_day` (ระบบคำนวณให้ แสดงให้สมาชิกเห็นก่อนแจ้งชำระ)

## 4. User Flows (MVP)

### 4.1 สมาชิก — สั่งอาหาร + เลือกไข่
1. เปิดลิงก์ LIFF จากในแชต → LINE Login อัตโนมัติ → เข้าหน้า "สัปดาห์นี้"
2. เห็นเมนูราย��ัน จ–ศ + ราคา/วัน
3. แตะเลือกวันที่จะกิน (กดทีละวัน หรือ "เลือกครบ 5 วัน")
4. แต่ละวันที่เลือก → เลือกชนิดไข่ (ต้ม/ดาว/เจียว/ไม่เอา) + ระดับสุก/หมายเหตุ (ถ้ามี)
5. เห็นสรุปยอดเงินรวม → กด "บันทึกออเดอร์"
6. แก้ไขได้จนกว่าสถานะสัปดาห์จะ "ปิด" (closed) หรือถึงเส้นตายพฤหัสบดี

### 4.2 สมาชิก — แจ้งชำระเงิน
1. ในหน้าออเดอร์ของสัปดาห์ → กด "แจ้งชำระเงิน"
2. เลือกวิธี: **อัปโหลดสลิป** (เลือกรูปจากเครื่อง/ถ่าย) หรือ **เงินสด**
3. ส่ง → สถานะ = "รอแอดมินยืนยัน"
4. เห็นสถานะอัปเดตเมื่อแอดมินกดยืนยัน/ปฏิเสธ (พร้อมเหตุผลถ้าถูกปฏิเสธ)

### 4.3 แอดมิน — แพลนเมนู (ปฏิทินรายเดือน) + รอบบิลรายสัปดาห์
**แพลนเมนูเป็นปฏิทินรายเดือน** (ดูภาพตัวอย่าง "June 2026"): แต่ละวันทำการมี
1 เมนู + **ชื่อคนเลือก/รับผิดชอบ** (เช่น "พี่อีฟ", "พี่แอน") และ marker **วันหยุด**
1. หน้า Admin → ปฏิทินเดือน → กดวัน → ใส่ชื่อเมนู + **คนเลือก** (เลือกจากรายชื่อสมาชิก
   หรือพิมพ์ชื่ออิสระเพิ่มเองได้) + รูป/หมายเหตุ, หรือ mark เป็น **วันหยุด** (ไม่มีออเดอร์/ไม่คิดเงิน)
2. **รอบบิล (สัปดาห์ จ–ศ):** สร้าง week plan + ตั้งราคา/วัน + deadline (พฤหัส) ผูกกับวันที่ในปฏิทิน
3. กด "เปิดให้สั่ง" (open) → สมาชิกเริ่มสั่งได้
4. เมื่อถึงกำหนด กด "ปิดรับ" (closed) แล้ว "ออกบิล/เก็บเงิน" (billed)
5. มีปฏิทินเดือนแบบ **print/share** (ตรงกับที่โพสต์ในกลุ่ม — "reprint when updated")

### 4.4 แอดมิน — ยืนยันการชำระเงิน
1. หน้า "คิวชำระเงิน" ของสัปดาห์ → เห็นรายการที่ "รอตรวจ" พร้อมรูปสลิป/ระบุเงินสด + ยอด
2. กด **ยืนยัน** (confirmed) หรือ **ปฏิเสธ** (rejected + เหตุผล)
3. Dashboard อัปเดต: ใครจ่ายแล้ว / ใครค้าง / ยอดรวมที่ได้รับ

### 4.5 แม่ครัว/แอดมิน — สรุป (ตาราง + ยอดนับ)
สรุปมี **2 มุมมอง** (อ้างอิงสรุปจริงในกลุ่ม):

**(ก) ตารางสรุปรายสัปดาห์ (Order Grid)** — เหมือนภาพ "Lunch 22–26 Jun 2026"
- แถว = **รายชื่อสมาชิกทั้งหมด** (รวมคนที่ไม่สั่ง), คอลัมน์ = จ–ศ
- ช่อง = ชนิดไข่ (ต้ม / ดาวสุก / ดาวไม่สุก / เจียว) หรือ **"ไม่ทานไข่"** หรือ **"ไม่กิน"**
- ไฮไลต์คนที่ "ไม่กิน" ทั้งสัปดาห์; ใช้สีแยกสถานะให้อ่านง่าย
- ปุ่ม **print / export เป็นรูป** + คัดลอกข้อความ (ตรงกับที่โพสต์ในกลุ่ม)

**(ข) ยอดนับรายวัน (Cook Count)** — สำหรับแม่ครัว
1. เลือกวัน → หัวทั้งหมดที่กิน, นับ ต้ม X / ดาวสุก Ya / ดาวไม่สุก Yb / เจียว Z / ไม่ทานไข่ W
2. รายชื่อ + หมายเหตุพิเศษ (เช่น "ไม่ใส่ผัก")
3. **รายชื่อคนที่ "ไม่สั่งข้าว" วันนั้น** (ตรวจง่าย ๆ ว่าใครยังไม่สั่ง)
4. ปุ่มแชร์/คัดลอกข้อความสรุป

### 4.6 แอดมิน — ค้นหา (Search)
1. หน้า "คิวชำระเงิน" และ "สรุปแม่ครัว" มี **ช่อง Search** ค้นหาตามชื่อสมาชิก (`display_name`)
2. พิมพ์ชื่อ → กรองรายการแบบทันที (debounce), ค้นแบบไม่สนตัวพิมพ์เล็ก/ใหญ่
3. ใช้ร่วมกับตัวกรองสถานะการจ่ายเงินได้ (เช่น ค้นหา "แอน" + กรอง "ค้างชำระ")
4. ช่วยแอดมินหาคนเฉพาะรายได้เร็วเมื่อสมาชิกในกลุ่มมีจำนวนมาก

## 5. Business Rules

- **รอบบิล = สัปดาห์ (จ–ศ).** **จ่ายล่วงหน้า:** ปิดรับ/เก็บเงิน = **พฤหัสบดีก่อนสัปดาห์ที่กิน**
  (ADR-0007) — สอดคล้องกับแชตจริงที่เก็บวันพฤหัสสำหรับ "อาทิตย์หน้า"
- 1 สมาชิก = 1 ออเดอร์/สัปดาห์ (มีรายการได้หลายวัน); วันหยุดสั่งไม่ได้/ไม่คิดเงิน
- แก้ออเดอร์ได้เฉพาะตอนสถานะสัปดาห์ = `open` และยังไม่เลย deadline
- **ล็อกออเดอร์เมื่อ payment = `confirmed`** (ADR-0010): สมาชิกแก้จำนวนวันไม่ได้หลังยืนยันแล้ว
  จะแก้ต้องให้แอดมิน reopen — กันยอดที่จ่ายไม่ตรงกับออเดอร์
- ยอดชำระคำนวณจากจำนวนวันที่สั่ง × ราคา/วัน (ระบบไม่ตรวจสลิปอัตโนมัติ — แอดมินยืนยันเอง)
- **การชำระเก็บแบบ append-only** (ADR-0009): ถูกปฏิเสธแล้วแจ้งใหม่ → เก็บทุกครั้ง, อันล่าสุด = ปัจจุบัน
- **รายชื่อสมาชิก (roster):** แอดมินสร้างล่วงหน้าได้ แล้วผูกบัญชี LINE ตอน login ครั้งแรก (ADR-0008)
  → ตารางสรุปโชว์ครบทุกคน รวมคนที่ยังไม่เปิดแอป
- การยืนยัน/ปฏิเสธทำได้เฉพาะ role `admin`
- การปฏิเสธต้องมีเหตุผล (เก็บ log + แจ้งสมาชิก)
- สลิปเป็นข้อมูลส่วนตัว → เก็บใน private storage, เข้าถึงผ่าน signed URL เท่านั้น
  (เจ้าของออเดอร์ + admin เห็นได้)

## 6. Non-functional Requirements

- **Mobile-first:** ทำงานหลักใน LINE in-app browser (LIFF) บนมือถือ
- **Performance:** First load เร็ว (โหลดในเว็บวิวของ LINE), รูปสลิป optimize/ย่อขนาด
- **i18n:** ภาษาไทยเป็นหลัก (เลขวัน จ–ศ, ฟอนต์ไทยอ่านง่าย)
- **Accessibility:** แตะง่ายบนมือถือ (touch target ≥ 44px), contrast ผ่าน WCAG AA
- **Security/Privacy:** verify LINE identity ฝั่ง server, RLS ปิดข้อมูลข้ามคน, สลิป private
- **Auditability:** เก็บ log การยืนยัน/ปฏิเสธ (ใคร/เมื่อไหร่)
